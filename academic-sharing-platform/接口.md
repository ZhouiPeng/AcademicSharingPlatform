# 一、通用接口约束（所有接口必须遵守）
## 1.1 接口风格
遵循 RESTful 规范：GET=查询、POST=创建、PUT=修改、DELETE=删除

## 1.2 统一响应格式
```json
{
  "code": 1, // 1为成功，0（默认）及其他为失败（具体错误码按接口定义）
  "msg": "操作成功", // 成功时提示信息，失败时返回具体的错误提示
  "data": {}, // 业务数据（根据接口返回具体结构）
  "timestamp": 1699999999999 // 服务器时间戳（毫秒）
}
```

> 说明：原文中将 `code` 作为 HTTP 状态码的做法已统一为业务码，HTTP 状态仍可通过响应头返回（如 200/400/500），业务侧以 `code` 字段判断具体业务成功/失败。

## 1.3 分页参数统一
URL 查询参数统一采用 `pageNum` 与 `pageSize`，默认 `pageNum=1`，`pageSize=10`。例如：
```
?pageNum=1&pageSize=10
```

## 1.4 枚举值统一
以下为项目常用枚举示例（统一放在第一章，后续接口使用时引用编号）：
```json
{
  "roleType": { "1": "科研人员", "2": "普通用户", "3": "管理员" },
  "achievementType": { "1": "期刊论文", "2": "专利", "3": "科研项目", "4": "奖项" },
  "privacyLevel": { "1": "公开", "2": "机构内可见", "3": "私有" },
  "classification": {
    "100": {
      "name": "计算机科学",
      "sub": {
        "1001": "人工智能",
        "1002": "计算机视觉",
        "1003": "自然语言处理",
        "1004": "机器学习"
      }
    },
    "200": {
      "name": "电子信息",
      "sub": {
        "2001": "通信与信息系统",
        "2002": "信号与信息处理",
        "2003": "微电子学"
      }
    },
    "300": {
      "name": "材料科学",
      "sub": {
        "3001": "纳米材料",
        "3002": "能源材料",
        "3003": "复合材料"
      }
    }
  }
}
```

> 说明：`classification` 为分层枚举，第一层为学科大类（例如 100 为计算机科学），`sub` 为二级学科（例如 1001=人工智能）。如果需要更多学科，请在此处补充并同步到数据库/前端字典。

## 1.5 权限传递
默认所有接口均需在请求头携带：
```
Authorization: Bearer {Token}
```
特殊不需要 Token 的接口会在具体接口说明中明确标注。

## 1.6 文件交互规则
非结构化文件（PDF/头像等）在后端仅使用对象存储（例如华为云OBS）返回的 `fileId` 作为文件唯一标识，**不直接传递文件流**。

因此所有的请求头和返回头的 `Content-Type` 均应为 `application/json`（文件上传/下载由独立的存储服务或预签名 URL 处理）。

## 1.7 数据修改规则
涉及数据修改的 `PUT` 接口只需传入修改对象主键（`*Id`）以及 `data` 字段，`data` 中记录要修改的键名与修改内容，最小化传输体积。例如：
```json
{
  "achievementId": "ach001",
  "data": { "title": "新的标题", "privacyLevel": 2 }
}
```
